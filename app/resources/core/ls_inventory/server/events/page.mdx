# Events

Primary integration surface is **exports** and the **hook system** — see [Exports](/resources/core/ls_inventory/server/exports) and [Hooks](/resources/core/ls_inventory/server/hooks). Net events below are server -> client pushes that keep the NUI/ped state in sync; other resources rarely need them.

## Net events (server -> client)

| Event | Args | Description |
|---|---|---|
| `Inventory:Client:RefreshInventory` | – | Re-pull inventory after a server-side change |
| `Inventory:Client:CacheItems` | `items` | Push full item-definition cache |
| `Inventory:Client:ApplyEquippedClothing` | `clothingAppearances` | Apply equipped clothing to local ped |
| `Inventory:Client:OpenInventory` | `data` | Open inventory NUI with context |
| `Inventory:Client:CloseInventory` | – | Close inventory NUI |
| `Inventory:Client:ClearExternalInventory` | `inventoryId` | Close/clear a specific external (stash/drop) view |
| `Inventory:Client:EquipItem` | `data` | Force-equip an item client-side |
| `Inventory:Client:ItemConsumed` | `data` | Item consumed server-side (drop from hand if held) |
| `Inventory:Client:WeaponSlotCleared` | `{ slotType, itemName }` | Equipment slot cleared (weapon/clothing removed) |
| `Inventory:Client:WeaponCleanup` | – | Clear weapon state (e.g. admin wipe) |

```lua
AddEventHandler('Inventory:Client:RefreshInventory', function()
    -- inventory contents changed server-side
end)
```

## Inventory Event System

Export-based listener system with richer payloads. Runs **after** the action commits (use [Hooks](/resources/core/ls_inventory/server/hooks) to act before/veto).

```lua
---@alias InventoryEventType
---| "itemAdded"
---| "itemRemoved"
---| "itemMoved"
---| "itemUsed"
---| "itemSplit"
---| "itemStacked"
---| "inventoryOpened"
---| "inventoryClosed"
---| "inventoryCleared"

---@class InventoryEventData
---@field source number|nil
---@field characterId string|nil
---@field inventoryId string|nil
---@field itemId number|nil
---@field itemName string|nil
---@field metadata table|nil
---@field quantity number|nil
---@field timestamp number   -- os.time(), set automatically
```

Not every field is populated for every event — only the relevant ones.

## OnInventoryEvent

```lua
---@param eventType InventoryEventType
---@param callback fun(data: InventoryEventData): boolean|nil
---@return string handlerId
exports.ls_inventory:OnInventoryEvent(eventType, callback)
```

```lua
exports.ls_inventory:OnInventoryEvent('itemAdded', function(data)
    print(("%s x%d -> %s"):format(data.itemName, data.quantity, data.inventoryId))
end)
```

## OnAnyInventoryEvent

```lua
---@param callback fun(eventType: InventoryEventType, data: InventoryEventData): boolean|nil
---@return string handlerId
exports.ls_inventory:OnAnyInventoryEvent(callback)
```

```lua
exports.ls_inventory:OnAnyInventoryEvent(function(eventType, data)
    print(eventType, data.itemName, data.characterId)
end)
```

## OffInventoryEvent

```lua
---@param handlerId string
---@return boolean
exports.ls_inventory:OffInventoryEvent(handlerId)
```

```lua
local handlerId = exports.ls_inventory:OnInventoryEvent('itemAdded', function(data) end)
exports.ls_inventory:OffInventoryEvent(handlerId)
```

## Hooks vs Events

| | Hooks (`registerHook`) | Events (`OnInventoryEvent`) |
|---|---|---|
| Timing | before the action | after the action |
| Can block | yes, `return false` | no |
| Can mutate | yes (`addItem` metadata) | no |
| Filters | `itemFilter`, `inventoryFilter` | none |
| Cleanup | automatic on `onResourceStop` | manual |

> To block or modify an action, use [Hooks](/resources/core/ls_inventory/server/hooks). To react after the fact (logging, notifications), use Events.
