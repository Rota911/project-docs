# Drop System

Items dropped into the 3D world. Each drop owns an `inventoryId` (`drop:<id>`) and a set of item props. Drops are **not persistent** across restarts — `DestroyAll()` clears them on shutdown.

## Config

```lua
Config.DropSystem = {
    LoadDistance        = 50.0,                  -- client prop load radius, read once on start
    PickupDistance       = 2.0,                   -- interaction distance
    FallbackModel         = "prop_paper_bag_small",-- used when the item has no prop model
    DefaultGridWidth      = 6,
    DefaultGridHeight     = 4,
    PropSpacing           = 0.35,                  -- spacing between props (spiral layout)
    CleanupCronSchedule    = '*/1 * * * *',         -- expired-item sweep
    MergeRadius            = 1.5,                   -- merge a new drop into an existing one within this radius
    RarityDespawnTime = {                          -- seconds, per-item despawn by rarity
        legendary = 10800,
        epic      = 9000,
        rare      = 7200,
        uncommon  = 5400,
    },
    DefaultDespawnTime = 60,                        -- seconds, items without a rarity entry
}
```

> Despawn is **per item prop**, not per drop — each item gets its own `despawnAt` based on `itemDef.rarity`. There is no drop-level `lifetime`.

## CreateDrop

```lua
---@alias DropTarget vector3|number|string
---@alias DropSource DropItemEntry[]|string

---@param target DropTarget
---@param source DropSource
---@param options? DropOptions
---@return Result  -- data: { dropId: string, inventoryId: string, coords: vector3 }
exports.ls_inventory:CreateDrop(target, source, options)
```

### Target

| Type | Description |
|---|---|
| `vector3` | exact coords, heading defaults to `0.0` |
| `number` | server player ID — dropped near the player, randomized within `Config.DropSystem.DropRadius` |

> `target` does not accept a string — only `vector3` or a player server ID resolve to coords.

### Source

```lua
---@class DropItemEntry
---@field itemName string
---@field count?    number   -- default 1
---@field metadata?  table
---@field uses?      number
```

A list of `DropItemEntry` creates new items. A string inventoryId (`"character:10046"`, `"stash:28231"`) clones (or moves, with `clearSource = true`) that inventory's contents into the drop.

```lua
---@class DropOptions
---@field heading?     number   -- default: player's heading
---@field clearSource? boolean  -- empty the source inventory instead of cloning, default false
---@field gridWidth?   number
---@field gridHeight?  number
```

```lua
exports.ls_inventory:CreateDrop(
    vector3(200.0, -900.0, 30.0),
    { { itemName = "water", count = 3 }, { itemName = "bandage", count = 5 } }
)

exports.ls_inventory:CreateDrop(source, { { itemName = "lockpick", count = 1 } })

exports.ls_inventory:CreateDrop(
    vector3(100.0, -500.0, 25.0), "stash:28231", { clearSource = true }
)
```

## Drop structure

```lua
---@class DropItemProp
---@field itemId    number
---@field itemName  string
---@field model     string|number
---@field offset    vector3
---@field heading   number
---@field despawnAt number   -- os.time() + rarity/default despawn seconds

---@class Drop
---@field dropId      string
---@field inventoryId string       -- "drop:<id>"
---@field coords      vector3
---@field heading     number
---@field createdAt   number       -- os.time()
---@field gridWidth   number
---@field gridHeight  number
---@field itemProps   DropItemProp[]
```

## Automatic behavior

- **Empty drop cleanup.** When all items leave a drop (taken or moved), the drop is destroyed and viewers notified.
- **Merge.** A new drop placed within `MergeRadius` of an existing drop merges into it instead of creating a new one.
- **Despawn cron.** `CleanupCronSchedule` runs `CleanupExpiredItems`, removing item props past their `despawnAt` and destroying drops left empty.
- **Restart.** Drops persist to the database; `LoadFromDatabase` restores them on boot and immediately runs an expiry sweep.

## Net events (server -> client)

Sent automatically, no manual triggering needed.

| Event | Payload | Description |
|---|---|---|
| `Inventory:Client:CreateDrop` | `drop` (serialized) | New drop created |
| `Inventory:Client:RemoveDrop` | `{ dropId }` | Drop destroyed |
| `Inventory:Client:UpdateDrop` | `drop` (serialized) | Drop contents changed (prop redraw) |
| `Inventory:Client:SyncDrops` | `drop[]` | Full sync on character load / resource start |
| `Inventory:Client:ClearAllDrops` | – | All drops cleared (resource stop) |

Item props use the spiral layout from `PropSpacing`; model comes from `itemDef.prop.model`, falling back to `Config.DropSystem.FallbackModel`. Clicking a prop opens the drop's inventory via the same `OpenInventory` pipeline used for stashes.
